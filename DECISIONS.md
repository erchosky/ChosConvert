# Architecture Decision Records

Each entry: **Context · Decision · Alternatives · Consequences**. Newest last. Status values:
*Accepted*, *Superseded by ADR-x*, *Proposed*.

---

## ADR-0001 — Native apps over a shared Rust core
*Accepted · 2026-10-18*

**Context.** ChosConvert ships on macOS first and Windows later. Two fully separate conversion
engines would double bugs and drift; a cross-platform UI toolkit (Electron, Flutter, a WebView)
would not feel native and is explicitly excluded by the product spec.

**Decision.** UIs are fully native (SwiftUI/AppKit on macOS, WinUI 3 on Windows). Everything that
is platform-neutral lives in a Rust core: content detection, inspection models, capability
registry, conversion planning, FFmpeg execution (progress, cancellation), target-size
optimization, output naming/collisions, temp-space management, error model.

**Alternatives.** C++ core (weaker memory safety, worse tooling); Swift core shared via Swift on
Windows (immature WinUI interop); duplicate logic per platform (drift).

**Consequences.** Each app links a static library. Platform codecs (ImageIO, AVFoundation, WIC,
Media Foundation) stay in the apps behind the planner's engine abstraction. The core must build
on both platforms (CI enforces).

## ADR-0002 — C ABI exchanging versioned JSON
*Accepted · 2026-10-18*

**Context.** Swift and C# must call the core without depending on Rust layouts.

**Decision.** Eight `extern "C"` functions (`core/include/chosconvert_core.h`, generated by
cbindgen): `cc_abi_version`, `cc_core_version`, `cc_call(method, json)`, `cc_string_free`,
`cc_task_start(method, json, callback, user_data)`, `cc_task_cancel`, `cc_webp_encode`,
`cc_buffer_free`. Requests/responses are UTF-8 JSON with snake_case keys and an
`{"ok":…, "result"|"error":…}` envelope. Two version numbers: `CC_ABI_VERSION` (binary contract)
and `api_version` from `core.info` (JSON contract). Panics never cross the boundary.

**Alternatives.** UniFFI / swift-bridge (generated bindings per language, larger surface, extra
tooling for C#); flatbuffers/protobuf (schema tooling for marginal speed).

**Consequences.** Tiny, stable ABI; JSON cost is negligible next to media work. Bulk pixel data
uses a dedicated binary function (`cc_webp_encode`). Swift mirrors live in
`ChosConvertKit/Models/CoreModels.swift`; C# mirrors will be written for Windows.

## ADR-0003 — SwiftUI first, AppKit where needed; macOS 15 minimum
*Accepted · 2026-10-18*

**Context.** Current system is macOS 27 (Xcode 27.1, Swift 6.4). Apple supports the current and
two previous releases with security updates.

**Decision.** Deployment target **macOS 15.0**. SwiftUI with Observation for the app; AppKit for
panels, pasteboard, drag-out and (Phase 2) the Edge Dock `NSPanel`. Swift 6 language mode with
complete concurrency checking.

**Alternatives.** macOS 14 (loses newer SwiftUI APIs, adds availability noise); macOS 26 (cuts
users who haven't upgraded).

**Consequences.** Liquid Glass-specific styling must be availability-gated. Revisit yearly.

## ADR-0004 — Engine priority: native fast path, then FFmpeg
*Accepted · 2026-10-18*

**Context.** The spec prefers native APIs, yet needs codecs macOS lacks (MP3, Opus, VP9, AV1 encode,
MKV/WebM I/O) and fine rate control.

**Decision.**
- **Images:** ImageIO always (decode, color, encode); WebP output via the core's libwebp (ADR-0006).
- **Audio/video:** FFmpeg engine when the distribution includes it (precise rate control, remux
  per-stream, verification via ffprobe, hardware encoders through VideoToolbox), otherwise the
  AVFoundation engine (export presets, passthrough remux, metadata stripping via a media-only
  composition). The planner picks per intent and only lists actions some available engine can do.
- **PDF/OCR:** PDFKit and Vision on macOS (Phase 3).

**Alternatives.** FFmpeg for everything (worse HEIC/color handling, licensing weight); AVFoundation
for everything (no MP3/Opus/WebM, preset-only quality control).

**Consequences.** `CodecCapabilities` differ between builds; the UI is driven by the capability
registry, so a Store build without FFmpeg simply shows fewer formats. A full AVAssetWriter engine
with bitrate control (so the Store build gets "Balanced"/target size natively) is on the roadmap.

## ADR-0005 — FFmpeg licensing and distribution
*Accepted · 2026-10-18*

**Context.** The Homebrew FFmpeg on the development machine is a **GPL** build (`--enable-gpl`
with x264/x265). Shipping GPL code would force the whole app under GPL; `nonfree` builds cannot
be distributed at all.

**Decision.**
- Development: any FFmpeg found at a known path is used (Debug builds only, unsandboxed).
- **Direct** distribution: bundle an **LGPL-only** FFmpeg built from source with a recorded
  configuration (`--disable-gpl --disable-nonfree`, dynamic libs, VideoToolbox/AudioToolbox,
  libopus, libvpx, libmp3lame, libsvtav1, libdav1d), placed in `Contents/Helpers` with
  `com.apple.security.inherit`. Source offer + notices in THIRD_PARTY_NOTICES.
- **Store** distribution: no FFmpeg; native engines only (ADR-0004).
- The core reads `ffmpeg -version` and reports `license` (`lgpl`/`gpl`/`nonfree`); the planner
  never selects `libfdk_aac`. Release validation (RELEASE.md) fails if a bundled FFmpeg is not LGPL.

**Alternatives.** GPL app (incompatible with closed/commercial licensing choices still open);
no FFmpeg at all (loses MP3/WebM/AV1/precise target size on direct builds).

**Consequences.** Without x264, LGPL builds use VideoToolbox H.264/HEVC or SVT-AV1 for software
encoding; two-pass target size then uses VideoToolbox ABR + refinement (already supported).
The LGPL FFmpeg build script is a Phase 4 deliverable.

## ADR-0006 — WebP through bundled libwebp
*Accepted · 2026-10-18*

**Context.** ImageIO (and Windows WIC) decode WebP but cannot encode it; WebP output is core to
"Prepare for web".

**Decision.** The core links `libwebp-sys` (MIT bindings, libwebp BSD-3-Clause, statically
compiled from vendored source). The app decodes/color-manages, converts to straight-alpha RGBA,
and calls `cc_webp_encode`.

**Consequences.** Same WebP output on both platforms. WebP files are written in sRGB without an
ICC profile (documented in the plan step "Convert to sRGB").

## ADR-0007 — App Sandbox: on for Release, off for Debug
*Accepted · 2026-10-18*

**Context.** The product must be Store-ready (sandboxed), but sandboxed processes cannot execute
binaries outside the bundle such as a developer's Homebrew FFmpeg.

**Decision.** Release builds use `ChosConvert.entitlements` (sandbox, user-selected read-write,
app-scoped bookmarks, **no network**). Debug builds are unsandboxed. All file access goes through
code paths that work in both: `OutputAccess` asks once per folder (open panel preselecting that
folder) and stores a security-scoped bookmark; dropped files carry their own extensions.

**Consequences.** Sandbox-specific behavior must be tested on Release builds (manual checklist in
RELEASE.md). No network entitlement means the OS enforces offline operation in Release.

## ADR-0008 — Xcode project generated by XcodeGen
*Accepted · 2026-10-18*

**Decision.** `macos/App/project.yml` is the source of truth; the `.xcodeproj` is generated
(`xcodegen generate`) and not committed. All code lives in the `ChosConvertKit` Swift package
(testable with `swift test`); the app target is a thin shell plus resources and entitlements.

**Alternatives.** Committing `project.pbxproj` (merge conflicts); Tuist (heavier).

## ADR-0009 — Default codec for "Make smaller"
*Accepted · 2026-10-18*

**Decision.** macOS: HEVC (`hvc1`-tagged MP4) — about half the size of H.264 and universally
playable on Apple platforms. Windows: H.264 (HEVC playback needs a paid Microsoft extension).
HDR sources keep HDR via 10-bit HEVC; choosing H.264 explicitly warns that colors may look washed
out because no tone-mapping filter is available in LGPL builds.

## ADR-0010 — Target-size algorithm
*Accepted · 2026-10-18*

**Decision.** Budget = `target × 0.95 − container overhead` (overhead from frame and audio packet
counts). Audio bitrate from a ladder (160→32 kb/s, mono below ~150 kb/s total). Resolution: the
highest rung of `[source, 2160, 1440, 1080, 720, 540, 480, 360, 240]` (short side) whose
bits-per-pixel stays above the codec's floor; frame rate capped to 30 fps below 2.5 Mb/s.
Encoding: two-pass libx264 when available, else ABR with VBV limits. After each encode the real
size is evaluated: **accept** if `0.80·target ≤ size ≤ target` (overshoot never accepted);
otherwise refine — proportional on the first miss, then **secant interpolation inside the
over/under bracket** (encoders are non-linear; proportional steps oscillated in testing).
At most 2 refinements (3 encodes). The largest result under the target is kept; if none fits,
the job fails with `target_size_unreachable`.

**Evidence.** Acceptance test: 2.6 GB noisy 1080p source → 9.32 MB for a 10 MB target in 3
attempts. Pathological pure-noise 12 s clip → 1.60 MB for 2 MB.

## ADR-0011 — Architectures
*Accepted · 2026-10-18*

**Decision.** Release builds are **universal** (arm64 + x86_64): the Rust core is lipo'd
(`UNIVERSAL=1 scripts/build-core-macos.sh`) and Release sets `ARCHS = arm64 x86_64`. Apple
Silicon is the primary test platform. Debug builds are host-only for speed. The bundled FFmpeg
(Direct build) must also be universal; VideoToolbox constant-quality (`-q:v`) is only used on
arm64, x86_64 falls back to bitrate targets.

## ADR-0012 — Persistence
*Accepted · 2026-10-18*

**Decision.** Settings in `UserDefaults`. Recipes (Phase 3) as versioned JSON files validated by
a JSON Schema in `core/schemas`. History (Phase 3) as a local JSON-lines file in Application
Support with retention options. No database until a measured need appears.

## ADR-0013 — Temp files and finalization
*Accepted · 2026-10-18*

**Decision.** Each job gets `<tmp>/ChosConvert-Jobs/job-<uuid>` (0700) with a marker file. The
core only deletes directories that are direct children of the root, carry the marker and are not
symlinks; stale ones are removed at launch. Outputs are written to the job dir, verified, then
claimed at the destination with an atomic no-clobber hard link (or `O_EXCL` copy on file systems
without hard links), staged on the destination volume first. The source file is never a valid
target, even with "Replace".

## ADR-0014 — Damaged inputs are rejected
*Accepted · 2026-10-18*

**Context.** ImageIO decodes truncated JPEGs "successfully", filling the missing area with grey.

**Decision.** The core checks end-of-stream markers (JPEG EOI, PNG IEND, GIF trailer) and reports
`truncated`; inspection fails with `corrupt_file` instead of silently producing a damaged result.

## ADR-0015 — Localization
*Accepted · 2026-10-18*

**Decision.** One String Catalog (`ChosConvertUI/Resources/Localizable.xcstrings`) with English
(source) and Spanish. Views use semantic keys only. Core error codes, recovery ids, plan steps and
plan notes map to `error.*`, `recovery.*`, `step.*`, `note.*`. `scripts/check-l10n.py` (CI) fails
when any key used by the UI or emitted by the core lacks an `en`/`es` value or the format
specifiers differ.

## ADR-0016 — Offline by construction
*Accepted · 2026-10-18*

**Decision.** No networking code or SDKs; no analytics; no update checks. Release entitlements
omit `com.apple.security.network.client`, so the sandbox blocks any accidental connection.
`scripts/check-offline.sh` (CI) fails if networking APIs appear in app or core sources.

## ADR-0017 — Edge Dock drag detection without event monitors
*Accepted · 2026-10-18*

**Context.** The Edge Dock must appear only while files are being dragged anywhere on the system,
without Accessibility permission and without global key/mouse monitors (both are privacy
red flags, and global monitors need permission prompts on current macOS). A window that is always
on screen at the edge would intercept clicks on scroll bars, window edges and the macOS Dock.

**Decision.** `DragSessionWatcher` samples `NSEvent.pressedMouseButtons` every 120 ms. Only while
the primary button is held does it read `NSPasteboard(name: .drag).changeCount`. A change since the
last button release, with `public.file-url` among the pasteboard *types*, starts a session. The
release ends it. Contents are read only by the drag destination once the user drags onto the dock.
While the dock is enabled the app holds a `.userInitiatedAllowingIdleSystemSleep` activity so App
Nap doesn't stretch the timer. Panels are ordered in only during a session.

**Alternatives.** `NSEvent.addGlobalMonitorForEvents(.leftMouseDragged)` (a global monitor, excluded
by the spec); `CGEventTap` (needs Accessibility/Input Monitoring); an always-present 1–2 pt window
(steals edge clicks, and transparent pixels don't receive drags unless the window catches all
mouse events); a "shake to show" gesture (needs a global monitor).

**Consequences.** Idle cost is a few button-state queries per second and no pasteboard reads. App
Nap is off while the dock is enabled (documented; turning the dock off restores it). File-promise
drags (Photos, Mail) don't arm the strip. If a future macOS gates the drag pasteboard's type list
behind a prompt, this must be revisited (manual checklist in docs/EDGE_DOCK.md).

## ADR-0018 — Edge Dock windows and geometry
*Accepted · 2026-10-18*

**Decision.**
- One borderless, **non-activating** `NSPanel` per eligible display, keyed by the display UUID,
  rebuilt on screen-parameter changes. Level `.statusBar`; collection behavior
  `canJoinAllSpaces + stationary + ignoresCycle + fullScreenAuxiliary`.
- One AppKit `NSDraggingDestination` per panel (the hosting view is unregistered). SwiftUI targets
  report their frames in a named coordinate space and the controller hit-tests the drag location.
  Nested SwiftUI drop zones would fire enter/exit churn while the window grows from strip to
  panel.
- Strips sit on the visible-frame edge (beside a side-mounted macOS Dock). Edges shared with
  another display are cut out; only the longest free segment ≥ 160 pt gets a strip. The expanded
  window reaches the screen edge, so the pointer stays inside after expanding.
- Full-screen opt-out: when a drag begins, a normal-layer window from another process whose bounds
  equal a display's frame (`CGWindowListCopyWindowInfo`; geometry only, no titles, no Screen
  Recording permission) suppresses that display's strip.
- Geometry rules are pure functions (`EdgeDockGeometry`) covered by unit tests with synthetic
  mixed-scale arrangements.

**Alternatives.** One window spanning all displays (breaks with mixed scale factors and separate
Spaces); private CGS APIs to query Space type (not allowed in the Mac App Store, fragile).

**Consequences.** A borderless game window that exactly covers a display is treated as full screen
(desired). Behaviour that only the window server shows (Spaces, real drags) is covered by the
manual multi-monitor checklist.

## ADR-0019 — Edge Dock starts jobs immediately with default intents
*Accepted · 2026-10-18*

**Context.** The Edge Dock exists to skip the main window. A configuration sheet would defeat it.

**Decision.** Hovering inspects the files (core `detect.path` via `Inspector`, then
`actions.for_files`; up to 24 files, cached for the drag session). The panel lists one drop target
per action with fixed defaults (make smaller *balanced*; 10/25 MB; the four preferred convert
formats the planner offers; original-stream audio extraction; resize 1920 px / 1080p; 5 s GIF;
location/all metadata removal). Jobs go through the shared `AppModel.enqueue` (same queue,
output policy and encoder preference) without touching main-window navigation. Dropping on the
card instead of a target *holds* the files: actions become clickable buttons. This also covers
the sandboxed case where a file is readable only after the drop. "Open in ChosConvert" hands
the files to the main window for full configuration.

**Consequences.** No fake options: targets only exist for actions the planner accepted. Progress is
real (the queue's), and results offer reveal and drag-out. The card lingers 8 s after completion.

## ADR-0020 — App-wide model, menu bar extra and window routing
*Accepted · 2026-10-18*

**Decision.** `AppDelegate` owns the single `AppModel` (previously `@State` in the window scene).
The Edge Dock, menu bar extra and Finder "Open With" therefore work before, or without, the main
window. `bootstrap()` is idempotent (launch, window and tests may all call it). A SwiftUI
`MenuBarExtra` (menu style, can be hidden in Settings) offers *Open ChosConvert*, jobs in progress,
*Recent Results* (session-only, reveal in Finder; persistent history stays Phase 3), the Edge Dock
switch, Settings and Quit. AppKit surfaces reopen the main window through the SwiftUI
`openWindow` action, captured by the window and the status item label (`mainWindowOpener`).

**Consequences.** Closing the window keeps the app running (already the case). Recent results don't
survive relaunch until History lands.

## ADR-0021 — Command palette (⌘K)
*Accepted · 2026-10-18*

**Decision.** An in-window overlay (not a separate panel), opened from *Go › Command Palette…* (⌘K),
which also brings the main window forward. Commands: intents (Convert to …, Make smaller, Compress
video, Privacy Safe = remove all personal metadata, Fit a size, Extract audio, Prepare for web,
Resize, GIF, metadata/location removal) and navigation (Queue, Convert, Add Files, Settings, Edge
Dock on/off, Clear finished, Cancel all). With files loaded, intents come from the planner's smart
actions. Unavailable ones stay listed but disabled, with a reason. Without files, picking an
intent opens the file picker and the intent continues after inspection. Intents open the
configurator preset (format preselected) rather than running blind, so the plan preview and
estimate are still shown. Matching is case/accent-insensitive with word-prefix, bilingual
keyword and in-order-character scoring.

**Alternatives.** A global hotkey panel (needs a hot-key registration and a second window
architecture; deferred with "configurable shortcuts"); running intents directly (hides the plan).

## ADR-0022 — Completion notifications
*Accepted · 2026-10-18*

**Decision.** Opt-out setting (existing *Notify me when long conversions finish*, default on). A
notification is considered only for jobs that completed or failed after running ≥ 8 s, and only
when ChosConvert isn't the active app. Jobs finishing within 1.5 s of each other are coalesced
("3 files are ready" / "2 finished, 1 failed"). Authorization is requested the first time a
notification is actually due, never at launch. Clicking a single-result notification reveals the
file in Finder. Notification Center is skipped when not running from an app bundle (tests).

**Consequences.** Users who never run long jobs never see a permission prompt. The decision and the
text are unit-tested (`CompletionNotifier.shouldNotify`, `.content`). Delivery itself is manual.
